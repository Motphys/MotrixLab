# MotrixSim GPU 实施与验收

以 `e98888a5df951fd3c67da6cbcdfb7fc2008801e8` 为实现起点和 CPU 性能对照。本机结果记录于能力调查。设备语义和训练范围见[设计](../design/motrixsim-gpu.md)，SDK 小场景与对照方法见[能力调查](../research/motrixsim-gpu-backend-review.md)。

## 实施顺序

1. **建立 CPU 对照**。从环境 registry 枚举内置 Direct 和 Manager 任务，记录任务名、配置、seed、环境数与输入。先在独立的 CPU 安装中运行构造、初始化、step 和 reset，保存可复现命令与结果。
2. **接通首个 CUDA 场景**。验证可选依赖能单独安装，使仿真设备选择从环境入口到达 MotrixSim 插件。用无接触任务走通批量读写、物理步和局部 reset，再用接触任务与传感器检查 SDK 能力。
3. **覆盖两类环境**。按任务实际使用的查询、写入和随机化项扩展支持。检查构造期常量、随机采样、动作和观测的设备位置，复用现有 CPU 生命周期验证。先用现有测试或一次性脚本验收；实现与提交拆分确定后，再为长期行为契约补测试。
4. **接通训练与回放**。验证单进程 provider 后再接入异步 FastSAC 分片。将实际仿真设备写入运行记录，验证回放默认选择与显式覆盖。接口确定后同步更新中英文安装、训练和回放指南。
5. **执行任务与性能矩阵**。CPU 和 NVIDIA CUDA 使用独立安装环境，在同一候选提交运行。对每个任务记录通过、失败或受限及具体原因；缺少硬件的跳过项保留为待验收。

## 验收矩阵

| 项目 | 执行与判定 |
| --- | --- |
| 安装与设备 | 仅装 CPU 依赖时完成 CPU 矩阵。另在 NVIDIA 主机安装可选依赖并运行真实仿真。分别验证显式请求缺依赖、不可用卡号和缺少场景能力时的诊断。 |
| 任务与回合 | 所有内置任务在 CPU 和 CUDA 上完成构造、初始化、step 和局部 reset。核对终止、截断及自动 reset 前的终态观测。代表性短训覆盖无接触、持续接触、随机化与传感器任务。 |
| 局部 reset | 在多行接触场景复位部分行，对照目标行与保留行的物理状态和回合计数。分别检查复位后、下一物理步和下一次传感器采样的可观察结果。 |
| 训练与回放 | 用原有配方运行 SKRL、RSLRL 和 FastSAC 的适用组合；核对 learner 更新、记录的仿真设备、默认回放和显式 CPU 覆盖。异步 FastSAC 在 CPU 多 NUMA 和 CUDA 多卡上另验分片归属、实际推进与样本摄入。 |
| CPU 扩展 | 在同一主机用相同任务与配方对照基线和候选提交。分别增加物理核与 NUMA 节点数，比对吞吐、近线性区间及饱和点。 |
| CUDA 扩展 | 先增加单卡环境数找出饱和区间，再增加 GPU 数。检查每卡持续推进独立分片，分别报告独立仿真、端到端训练吞吐与主机传输开销。 |

多资源对照同时测强扩展（总环境数固定）和弱扩展（每单位资源的环境数固定）。扩展效率取相对最小布局的吞吐倍数除以资源倍数。记录基线和候选 SHA、硬件、SDK 与驱动、资源绑定、环境数、预热、计时窗口和实际命令；CUDA 计时窗口须覆盖设备完成工作所用的时间。
